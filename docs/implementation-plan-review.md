## Release gate present in code

`package.json` now includes `check:contact-resources`, `check:teaching-content` and combined `check:plan-review` in `verify`. `check:priority-eight` combines claim drift/staleness, visitor-measurement/report checks and AI memory/recovery checks. `prebuild` runs claim reconciliation before a production build. `build` regenerates the corpus, bundles the app and prerenders the 27 public routes. `docs/portfolio-maintenance.md` records how to run and interpret those gates and when to review sources manually.

The gate is meaningful because a due date, missing source or bound-value drift can fail a new build. `check-public-http.mjs` also asserts that each actual initial-HTML `href="#…"` has a matching target, covering the Product collection-link correction. The gate does not run a new external source refresh, human study or model-quality assessment. Do not move a source-checked date merely to make the gate pass.

Final release checks should record the actual command/result and exercise at least:

1. Fresh full verification/build and preview/HTTP responses for the current artifact, including the new pages, true 404, `/cv` and `/presentation`.
2. Desktop and phone navigation, all reader exits, exact return fragments, Work results/qualifications and Contact/AI dock clearance.

4. AI failure/retry/cancel, feedback acknowledgement and route memory using approved offline fixtures while provider/account review remains deferred.
5. The deployed public response and important external proof/resource destinations after deployment; a push or local build alone is not production verification.
